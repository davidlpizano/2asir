# 4. ReplicaSets

[Volver al índice](../README.md)

Un ReplicaSet garantiza que un número determinado de réplicas de un pod se estén
ejecutando en todo momento. Es una capa importante para asegurar la alta
disponibilidad de la aplicación.

## ¿Para qué sirve?

Si un pod falla o desaparece, el ReplicaSet detecta el problema y crea un nuevo
pod para mantener el número deseado de réplicas.

## Ejemplo

```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: mi-replicaset
spec:
  replicas: 3
  selector:
    matchLabels:
      app: mi-app
  template:
    metadata:
      labels:
        app: mi-app
    spec:
      containers:
        - name: app
          image: nginx:latest
```

## Diferencia con un Deployment

Aunque ambos gestionan réplicas, el Deployment es la opción más habitual en
producción porque ofrece un control más cómodo para actualizaciones y rollbacks.
ReplicaSets son útiles para entender la base del escalado y la disponibilidad.
